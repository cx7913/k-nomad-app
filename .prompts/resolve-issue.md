## 📋 작업 프로세스

### Step 1: 이슈 정보 가져오기

먼저 GitHub CLI를 사용하여 이슈 내용을 가져오세요:

```bash
gh issue view $ARGUMENTS
```

이슈의 다음 정보를 확인하세요:
- 제목 (Title)
- 본문 (Body)
- 라벨 (Labels)
- 담당자 (Assignees)
- 댓글 (Comments)

---

### Step 2: 이슈 분석

가져온 이슈를 다음 관점에서 분석하세요:

#### 1. 이슈 유형 분류
- [ ] **Bug** - 기존 기능의 오류
- [ ] **Feature** - 새로운 기능 요청
- [ ] **Enhancement** - 기존 기능 개선
- [ ] **Refactoring** - 코드 구조 개선
- [ ] **Documentation** - 문서 작업
- [ ] **Performance** - 성능 최적화
- [ ] **Security** - 보안 이슈

#### 2. 우선순위 평가
- **Critical** - 서비스 중단, 즉시 해결 필요
- **High** - 주요 기능 장애, 빠른 해결 필요
- **Medium** - 일반적인 개선, 계획된 해결
- **Low** - 사소한 개선, 여유있게 처리

#### 3. 핵심 문제 파악
**무엇이 문제인가?**
- 현재 상태 설명
- 예상되는 정상 동작
- 실제 발생하는 동작

**왜 문제인가?**
- 사용자에게 미치는 영향
- 비즈니스에 미치는 영향

**어디서 문제가 발생하는가?**
- 영향받는 컴포넌트/모듈
- 관련 파일 경로

---

### Step 3: 코드베이스 조사

이슈와 관련된 코드를 조사하세요:

#### 관련 파일 검색
```bash
# 키워드로 파일 검색
rg "키워드" --type ts --type tsx

# 함수/클래스 정의 찾기
rg "function 함수명|class 클래스명"
```

#### 조사할 항목
- [ ] 문제가 발생하는 파일 확인
- [ ] 관련된 컴포넌트/모듈 파악
- [ ] 현재 구현 방식 이해
- [ ] 의존성 확인
- [ ] 테스트 코드 존재 여부
