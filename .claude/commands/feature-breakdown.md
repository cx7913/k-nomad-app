# 기능 분해 커스텀 커맨드 (Feature Breakdown Custom Command)

복잡한 개발 작업을 체계적으로 분해하여 실행 가능한 작업 단위로 나눕니다.

## 구현하고 싶은 기능

$ARGUMENTS

---

당신은 복잡한 개발 작업을 실행 가능한 작은 단위로 분해하는 전문가입니다.
주어진 기능을 분석하고, SOLID 원칙을 준수하면서 점진적으로 구현할 수 있는 체계적인 계획을 수립하세요.

다음 구조로 분석해 주세요:

## 3. 📋 작업 분해

각 작업을 다음 형식으로 나열하세요 (1-4시간 내 완료 가능한 크기):

### [우선순위: High/Medium/Low] 작업명

- **설명**: 구체적인 작업 내용
- **예상 시간**: 1-4시간
- **의존성**: 선행 작업 명시 (없으면 "없음")
- **완료 조건**:
  - [ ] 언제 완료로 볼 수 있는지 체크리스트 형식
  - [ ] TypeScript 타입 체크 통과
  - [ ] 빌드 성공
- **파일/경로**:
  - 수정할 파일들
  - 생성할 파일들

## 4. 🔄 의존성 관계

### 병렬 처리 가능
동시에 진행할 수 있는 작업들을 그룹화하세요.

### 순차 처리 필요
반드시 순서대로 해야 하는 작업들을 나열하세요.
```
작업 A → 작업 B → 작업 C
```

### 블로커
리스크가 높거나 먼저 해결해야 할 작업들:
- 기술적 불확실성이 있는 항목
- 외부 의존성이 있는 항목
- 아키텍처 결정이 필요한 항목

## 📋 작업 분해 원칙

1. **원자성**: 각 작업은 하나의 명확한 목적만 가짐
2. **독립성**: 가능한 한 다른 작업과 독립적으로 실행 가능
3. **테스트 가능성**: 각 단계의 완료를 검증할 방법이 있어야 함
4. **점진성**: 각 단계 완료 후에도 시스템이 작동해야 함
5. **현실성**: 1-4시간 내 완료 가능한 크기로 분해
6. **추적성**: 진행 상황을 명확히 파악할 수 있는 체크리스트

- 각 작업별 명확한 시작/완료 조건
