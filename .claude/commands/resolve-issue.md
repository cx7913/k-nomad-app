  # GitHub 이슈 해결 계획

  GitHub 이슈를 분석하고 해결을 위한 상세한 실행 계획을 수립합니다.

  ## 이슈 번호

  $ARGUMENTS

  ---

  당신은 GitHub 이슈를 분석하고 체계적인 해결 계획을 수립하는 소프트웨어 아키텍트입니다.

  ## 작업 흐름

  ### 1단계: 이슈 가져오기

  1. **GitHub CLI 확인**
     - `gh --version`으로 설치 확인
     - 설치 안 되어 있으면 설치 방법 안내
     - `gh auth status`로 인증 상태 확인

  2. **이슈 조회**
     - `gh issue view $ARGUMENTS` 명령어로 이슈 상세 정보 가져오기
     - 이슈 제목, 본문, 라벨, 담당자, 코멘트 등 모든 정보 수집
     - 관련 PR이 있다면 함께 확인

  3. **이슈 분석**
     - 이슈 유형 파악 (버그, 기능 요청, 개선, 문서화 등)
     - 심각도 및 우선순위 확인
     - 영향 범위 추정

  ### 2단계: 코드베이스 탐색

  1. **관련 코드 찾기**
     - 이슈에 언급된 파일, 함수, 컴포넌트 검색
     - Grep, Glob 도구를 사용하여 관련 코드 위치 파악
     - 의존성 및 연관 파일 식별

  2. **현재 구현 이해**
     - 관련 파일들을 Read 도구로 읽어서 현재 구현 방식 파악
     - 아키텍처 패턴 및 코딩 스타일 확인
     - 기존 테스트 코드 확인 (있다면)

  3. **근본 원인 분석**
     - 버그인 경우: 재현 경로 및 원인 파악
     - 기능 요청인 경우: 기존 시스템과의 통합 방안 검토

  ### 3단계: 해결 계획 수립

  ## 💡 추가 옵션

  사용자가 원하면 다음 작업도 수행할 수 있습니다:

  - **상세 분석이 필요한 경우**: Task 도구의 Explore agent를 사용하여 코드베이스 심층 탐색
  - **아키텍처 설계가 필요한 경우**: Plan agent를 사용하여 더 정교한 설계
  - **즉시 구현 시작**: 사용자가 승인하면 바로 코드 작성 시작

  ## 오류 처리

  - **이슈 번호가 유효하지 않음**: "이슈 #$ARGUMENTS를 찾을 수 없습니다."
  - **gh CLI 미설치**: GitHub CLI 설치 방법 안내
  - **인증 오류**: `gh auth login` 실행 안내
  - **접근 권한 없음**: 저장소 권한 확인 안내
